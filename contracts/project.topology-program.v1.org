** What This Produces

This contract validates the separately admitted program projection for one
MRR-defined Project Topology. The stable Git-tracked Project Workspace
manifest is governed by =project.workspace-manifest.v1= instead. This contract
is distinct from =agent.topology.v1=, which describes imported project and
agent-session navigation.

The program projection binds one source snapshot, one standard MRR topology prelude, one
project Scheme/POO program, one compiled native ABI, one admitted MRR bundle,
one GitOps Project Workspace binding, and one materialized topology root. It
does not create an extension catalog, accept a Runtime-generated workspace id,
or embed a second inference language.

The corresponding machine contract is
[[file:../../schemas/project-topology-program-binding.v1.schema.json][project-topology-program-binding.v1]].

=REPOSITORY_ALIASES= uses one compact JSON array of unique, lexicographically
ordered canonical repository locators. The empty set is =[]=. It is property
data parsed through the native Org boundary, not an executable source block or
a second manifest grammar.

** program-has-identity
:PROPERTIES:
:ASSERT_ID: project-topology-program.has-identity
:SEVERITY: error
:END:

#+BEGIN_SRC org-contract
(let ((program
       (headline :at $scope)))
  (assert count >= 1
    (node-property :descendant-of program :summary (key "TOPOLOGY_PROGRAM_ID"))))
#+END_SRC

#+BEGIN_SRC jinja2 :name message
Project Topology program `{{ scope.title }}` must carry TOPOLOGY_PROGRAM_ID.
#+END_SRC
